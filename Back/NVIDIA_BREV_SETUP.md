# NVIDIA Brev для Career Quest

Инструкция подготовлена 23 сентября 2026 года по официальной документации NVIDIA. Облачные ресурсы пока не созданы; подключение к приложению появится при реализации backend AI-адаптера.

## 1. Для чего используем Brev

Для нашего проекта Brev — среда экспериментов с собственной языковой моделью на GPU. Предлагаемый вариант: NVIDIA NIM с HTTP API для ответов помощника по найденным статьям и объяснения рекомендаций. Обучать модель с нуля для этого не требуется.

```text
Front → Back → OpenAI API
             или
             → SSH-туннель → NIM на GPU в Brev

PostgreSQL и расчёт рекомендаций остаются в Back.
```

Кредиты Brev оплачивают инфраструктуру. Они не являются ключом доступа к OpenAI или автоматически выданным ключом hosted API NVIDIA. Для нашего варианта отдельно нужны аккаунт Brev, доступ к выбранному NIM и NGC-ключ для скачивания модели. NGC-ключ не заменяет защиту нашего inference API.

## 2. Подготовка на Mac

Открой [консоль Brev](https://brev.nvidia.com), войди в аккаунт, которому выданы $50, и проверь доступный баланс и организацию. Установи CLI через Homebrew и авторизуйся в браузере:

```bash
brew install brevdev/homebrew-brev/brev
brev --version
brev login
```

Источник: [Brev Quickstart](https://docs.nvidia.com/brev/getting-started/quickstart).

## 3. Выбор модели и GPU

В [каталоге NVIDIA](https://build.nvidia.com) выбери текстовую instruction/chat модель с вариантом самостоятельного развёртывания NIM. Проверь лицензию, доступность скачивания и требования к GPU, VRAM и диску на странице модели. Скопируй точное имя контейнера с тегом из её инструкции.

В Brev создай инстанс `career-quest-ai` в режиме **VM**, с Docker и NVIDIA runtime. Выбери GPU, поддерживаемую конкретным профилем модели. Перед подтверждением посмотри цену часа и хранения. Создание/запуск включает расход кредитов.

Подключение с Mac после готовности инстанса:

```bash
brev refresh
brev list
brev shell career-quest-ai
```

На удалённой VM проверь `nvidia-smi` и `docker --version`.

Источник требований NIM: [Deploying NVIDIA NIMs](https://docs.nvidia.com/brev/guides/inference-deployment/deploying-nims). Имя модели и тариф здесь намеренно не зафиксированы: их выбирают вместе по доступности, качеству RU/KZ и бюджету.

## 4. Запуск NIM на VM

На странице выбранного NIM выполни шаги получения NGC API key и доступа к контейнеру. Сохрани ключ как секрет окружения удалённой VM. Для разового ввода в **bash на VM** можно использовать скрытый ввод:

```bash
read -rsp 'NGC API key: ' NGC_CLI_API_KEY
export NGC_CLI_API_KEY
printf '\n'
printf '%s' "$NGC_CLI_API_KEY" | docker login nvcr.io -u '$oauthtoken' --password-stdin
```

Запусти контейнер по **команде со страницы выбранной модели**: требуемые параметры отличаются. Для нашей схемы измени публикацию порта на `-p 127.0.0.1:8000:8000`, сохрани кеш модели в volume и задай имя контейнера `career-quest-nim`. Передавай ключ через `-e NGC_CLI_API_KEY`, без значения в тексте команды. Убедись, что внутренний порт выбранного NIM действительно `8000`.

Дождись загрузки модели и готовности по логам:

```bash
docker logs --tail 100 -f career-quest-nim
```

Пример процедуры и параметры контейнера: [официальная инструкция NIM на Brev](https://docs.nvidia.com/brev/guides/inference-deployment/deploying-nims). Не открывай незащищённый inference-порт в интернет.

## 5. Доступ с Mac и проверка

В отдельном терминале **на Mac**, оставив процесс работающим:

```bash
brev port-forward career-quest-ai --port 8000:8000
```

В другом терминале на Mac:

```bash
curl --fail http://127.0.0.1:8000/v1/models
```

Скопируй точный ID модели из ответа. Для первого запроса:

```bash
curl --fail http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"REPLACE_WITH_MODEL_ID","messages":[{"role":"user","content":"Кратко объясни, что такое план развития сотрудника."}],"max_tokens":128}'
```

Замени `REPLACE_WITH_MODEL_ID`. Пример предполагает приватный локальный endpoint без дополнительного API-token; при настроенной авторизации запросу нужен соответствующий заголовок.

Если порт занят, используй `--port 8001:8000` и обращайся к локальному `8001`. Консольный публичный tunnel может требовать браузерную авторизацию; для запросов API здесь используем SSH forwarding. После перезапуска VM выполняй `brev refresh`.

Источник: [Brev Connectivity](https://docs.nvidia.com/brev/cli/connectivity).

## 6. Настройка нашего backend

После реализации адаптера в локальном `Back/.env`:

```dotenv
AI_PROVIDER=nim
NIM_BASE_URL=http://127.0.0.1:8000/v1
NIM_MODEL=REPLACE_WITH_MODEL_ID
NIM_API_KEY=
AI_REQUEST_TIMEOUT_MS=8000
```

Первую интеграцию выполняем с backend, запущенным непосредственно на Mac. В Docker `127.0.0.1` указывает на сам контейнер. Для контейнерного backend потребуется отдельно настроить и проверить доступ к туннелю на хосте; простая замена URL без проверки сети недостаточна.

Адаптер отправляет только разрешённый контекст: профиль текущего сотрудника, отобранные активности или актуальные статьи. Проверяет ответ и ID, ограничивает длину и время. При недоступности NIM возвращает детерминированные рекомендации или сообщение о недоступности чата. Переключение на платный OpenAI должно быть явной настройкой с учётом его отдельного бюджета.

`NIM_API_KEY` заполняется только при настроенной аутентификации inference endpoint. NGC-ключ в это поле не копируется. Для публичного развёртывания приложения вместо туннеля через личный Mac потребуется постоянное защищённое соединение серверов и управление секретами.

## 7. Расходы и завершение работы

Для планирования используем:

```text
доступные часы ≈ (остаток кредита − резерв − ожидаемое хранение) / цена GPU в час
```

Бюджет команды: $50, ориентир резерва $10. Подставь реальные цены из консоли. Учитывай время скачивания, прогрева и простоя: закрытие браузера или SSH не останавливает VM.

После эксперимента выполни на Mac:

```bash
brev stop career-quest-ai
```

Проверь состояние в консоли. У остановленного инстанса прекращается расход на вычисления, но хранение может продолжать оплачиваться. Если эксперимент завершён окончательно, сохрани нужные результаты вне VM и удали инстанс через консоль: удаление уничтожает его данные.

Источники: [стоимость состояний GPU Instances](https://docs.nvidia.com/brev/concepts/gpu-instances), [управление инстансом](https://docs.nvidia.com/brev/cli/instance-management).

## 8. Если что-то не работает

| Симптом | Проверка |
| --- | --- |
| `401/403` при скачивании | Права NGC-ключа, принятая лицензия и доступ к конкретной модели |
| Модель не помещается / OOM | Требования выбранного профиля NIM, объём VRAM, контекст и параллелизм |
| `Connection refused` | Готовность контейнера, правильный порт, работающий SSH-туннель |
| Ответ HTML вместо JSON | Запрос мог попасть на страницу браузерной авторизации tunnel; проверить URL |
| `Model not found` | Использовать ID из `/v1/models`, а не название контейнера |
| С Mac работает, из Back в Docker — нет | Проверить адрес хоста и доступ к tunnel из сети контейнера |
| Ответ слишком долгий | Прогрев, длина контекста, лимит токенов; сравнить p95 с лимитом ТЗ |

Для оценки пользы Brev сохраняем обезличенные тестовые вопросы, выбранные модель/GPU, задержку, соблюдение источников и стоимость эксперимента. Сравниваем с OpenAI на одинаковом наборе; подключение GPU само по себе не подтверждает качество помощника.
