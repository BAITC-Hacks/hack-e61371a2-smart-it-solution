# Путеводитель и ИИ-помощник: контракт backend

Все пути ниже относятся к `/api/v1`. Используются общие cookie-сессии, CSRF и формат `{ "data": ... }`; ошибки — общий контракт API. Все запросы требуют входа. Модуль не меняет `Front`.

### Форматы записи

Создание темы:

```json
{
  "slug": "it-access",
  "category": "IT",
  "sensitivity": "normal",
  "priority": 10,
  "active": true,
  "aliases": { "ru": ["vpn", "ноутбук"], "kk": ["қолжетімділік"], "en": ["laptop"] },
  "contexts": ["onboarding"]
}
```

`sensitivity`: `normal|sensitive`. Контексты: `onboarding|review|role_change|learning_start|learning_complete`.

Черновик (тексты ниже — примеры структуры, не регламент организации):

```json
{
  "topicId": "UUID",
  "locale": "ru",
  "title": "Название утверждаемой инструкции",
  "summary": "Краткое описание",
  "body": "Полный текст",
  "appliesWhen": "Условия применения",
  "steps": ["Проверенный шаг"],
  "resources": [],
  "tags": ["доступ"],
  "visibility": ["employee", "manager", "hr", "admin"],
  "departments": [],
  "aiAllowed": false,
  "synthetic": true
}
```

`resources`: массив `{label,url}`, только HTTPS. Текстовые поля содержат обычный текст; frontend должен выводить их с экранированием, без `innerHTML`. `departments=[]` означает все подразделения. Если список задан, принадлежность проверяется по профилю сотрудника; HR/admin без employee-профиля не получают такое содержимое в обычном поиске, но могут управлять им через `manage=true`.

Публикация: `{ "humanReviewed": true, "expiresAt": "2026-12-01T00:00:00Z" }`. Срок должен быть в будущем и не дальше 366 дней. `approved_by`, `reviewed_at`, владелец и номер версии назначаются сервером. Опубликованный и архивный текст защищён также триггером БД. Изменение осуществляется через новую версию. На `(topic_id, locale)` допустима одна опубликованная версия.

Контакт:

```json
{
  "label": "Демонстрационный приватный канал",
  "channel": "demo",
  "value": "Реальный контакт организации не настроен",
  "description": "Пояснение для демонстрации",
  "visibility": ["employee", "manager", "hr", "admin"],
  "departments": [],
  "confidential": true,
  "active": true,
  "synthetic": true,
  "verified": true,
  "expiresAt": "2026-12-01T00:00:00Z"
}
```

Каналы: `email|phone|url|demo`. Значения проверяются по типу; `demo` требует `synthetic=true`. При каждом изменении необходимо повторить `verified=true`, иначе подтверждение сбрасывается. Неактивные, просроченные или неподтверждённые контакты сотруднику и помощнику не выдаются. Контакты хранятся отдельно от версий статей: смена контакта применяется сразу ко всем маршрутам.

Маршрут: `{topicId,department:null,primaryContactId:"UUID",fallbackContactId:"UUID",urgency:"normal",active:true}`. Нужен хотя бы один контакт; `urgency=normal|urgent`. Запасной канал фильтруется независимо от основного. Для реальной чувствительной статьи публикация требует проверенного конфиденциального реального контакта. Синтетические материалы всегда обозначены отдельно и не создают вымышленных действующих контактов.

Для нейтрального запасного канала создайте тему со `slug=general-support` и проверенный маршрут. Помощник использует его, если подтверждённой инструкции нет. Для чувствительной ситуации используются только конфиденциальные каналы.

Отзыв: `{kind:"wrong_contact",comment:"Текст до 2000 символов"}`. Типы: `helpful|unhelpful|outdated|wrong_contact|incorrect`.

Ответы редактора используют имена полей SQL (`topic_id`, `ai_allowed`, `reviewed_at`, `expires_at` и т. п.). Контакты в выдаче сотруднику нормализованы: `{id,topicId,label,channel,value,description,confidential,synthetic,urgency,priority,verifiedAt,expiresAt}`. `priority=primary|fallback`.

Поиск: PostgreSQL FTS `simple`, дополнительно русская морфология, локализованные синонимы и теги. Это SQL-поиск; семантические эмбеддинги не включены. Просроченные, архивные, неактивные и недоступные пользователю материалы исключены в SQL. Помощник дополнительно требует `ai_allowed=true` и повторно проверяет доступность источников после ответа провайдера.

## ИИ-помощник

| Метод и путь | Доступ | Назначение |
| --- | --- | --- |
| `GET /assistant/threads` | Владелец | До 50 собственных действующих диалогов |
| `POST /assistant/threads` | Авторизованный | `{title?,locale?}`; по умолчанию `Career Quest`, `ru` |
| `GET /assistant/threads/:id` | Только владелец | Диалог и сообщения в хронологическом порядке |
| `DELETE /assistant/threads/:id` | Только владелец | Удалить диалог и сообщения |
| `POST /assistant/threads/:id/messages` | Только владелец | `{content:"Вопрос"}`, до 2000 символов; обязателен `Idempotency-Key` 8–160 символов |
| `GET /admin/ai/usage` | Только admin | Расход, остаток, число запросов, незакрытые резервы, пороги 50/80/95% |

HR/admin также не имеют доступа к чужому диалогу. Чужие ID возвращают `404`. Внешнему провайдеру не передаётся ID сотрудника, ФИО, почта, телефон, файлы, исходный dataset или чужие профили. Из вопроса убираются распознаваемые ключи, email, длинные цифровые идентификаторы и известные имена сотрудников. Это минимизация данных, а не обещание универсального обнаружения любых персональных данных. Пользовательский текст диалога хранится локально с доступом только владельцу; нельзя вводить документы, пароли и сведения о клиентах.

Диалог привязан к роли, профилю сотрудника и подразделению на момент создания. После изменения этого контекста прежний диалог перестаёт выдаваться (`404`); новые диалоги создаются с актуальными правами. Состояние аккаунта повторно проверяется перед сохранением ответа. При чтении истории и повторе `Idempotency-Key` заново проверяются ссылки на статьи, `ai_allowed`, срок действия, доступность контактов и принадлежность фактов текущему профилю. Если источник архивирован, доступ отозван или контакт больше не подтверждён, сохранённый текст скрывается с `fallbackReason=SOURCE_ACCESS_CHANGED`. Это относится и к дублированному ответу в пользовательской записи истории; приватный текст не остаётся доступным через replay.

Помощник использует:

- Собственные текущие роль, грейд, цель и проверенные расчёты навыков через `loadCareer`.
- Актуальные опубликованные статьи на языке диалога и контакты, доступные роли/подразделению.
- До трёх предыдущих собственных вопросов для коротких уточнений.

Модель выбирает идентификаторы подходящих фактов и источников из ограниченного набора. Сервер проверяет каждый ID и формирует текст из проверенных фактов/утверждённых шагов. Свободно сгенерированные политики, контакты, числовые факты и действия не принимаются. Для чувствительных тем используются проверенные инструкции без генеративного вызова. ИИ не изменяет цели, записи на мероприятия или кадровые решения.

Ответ на сообщение:

```json
{
  "id": "UUID",
  "threadId": "UUID",
  "content": "Ответ из проверенных материалов",
  "source": "fallback",
  "locale": "ru",
  "scope": "own",
  "citations": [{"id":"UUID","title":"Название","href":"/guide/articles/UUID","reviewedAt":"ISO date","synthetic":true}],
  "contacts": [],
  "facts": [{"id":"skill:SK001","text":"Проверенный факт","href":"/employees/EMP001/skills"}],
  "fallbackReason": "AI_DISABLED",
  "createdAt": "ISO date"
}
```

`source`: `ai` (выбор источников моделью), `fallback` (детерминированный подбор), `verified_script` (чувствительная ситуация). `usageId` есть, если был зарезервирован вызов. Отсутствие подтверждённой информации явно сообщается. Ссылки `href` — рекомендованные frontend-маршруты, не URL запросов backend.

Один ответ на диалог обрабатывается одновременно. Повтор того же ключа и сообщения возвращает сохранённый ответ; другой текст с прежним ключом — `409 IDEMPOTENCY_CONFLICT`; незавершённый запрос — `409 MESSAGE_PROCESSING`. После обрыва процесса повторное выполнение с новым ключом разрешается по истечении 30-секундного замка. Ограничения: 50 действующих диалогов, 100 пользовательских сообщений в диалоге, часовой лимит сообщений также действует в режиме без ИИ.

Диалоги истекают через `AI_RETENTION_DAYS` от создания, сразу перестают читаться и удаляются функцией `cleanupAssistantRetention(pool)` из worker. Финансовый журнал сохраняется без текстов сообщений и ключей API для сохранения лимита расходов. Удаление чата не обнуляет потраченный бюджет.

## OpenAI и расходы

По умолчанию `AI_ENABLED=false`: ключ и оплачиваемые ресурсы для работающей платформы не нужны. Модель не зафиксирована в коде. Для включения необходимо выбрать доступную вашему аккаунту модель и явно задать проверенные тарифы. NVIDIA Brev не подключается.

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `AI_ENABLED` | `false` | Разрешить внешние вызовы |
| `OPENAI_API_KEY` | пусто | Только серверный secret; не `VITE_*` |
| `AI_MODEL_FAST` | пусто | Модель чата с поддержкой structured outputs |
| `AI_MODEL_RECOMMEND` | модель чата | Модель выбора рекомендаций |
| `AI_INPUT_USD_PER_MILLION` | `0` | Проверенная максимальная цена входа среди обеих моделей |
| `AI_OUTPUT_USD_PER_MILLION` | `0` | Проверенная максимальная цена выхода среди обеих моделей |
| `AI_PROJECT_BUDGET_USD` | `40` | Общий пожизненный бюджет этого backend, максимум `50` |
| `AI_USER_DAILY_BUDGET_USD` | `0.5` | Суточный лимит пользователя, UTC |
| `AI_USER_REQUESTS_PER_HOUR` | `20` | Лимит внешних попыток и отдельно сообщений помощника |
| `AI_PROJECT_REQUESTS_PER_DAY` | `500` | Суточный лимит внешних попыток, UTC |
| `AI_TIMEOUT_MS` | `7000` | Общий таймаут внешнего вызова с повтором, максимум `9000` |
| `AI_MAX_OUTPUT_TOKENS` | `800` | Ограничение выходных токенов |
| `AI_MAX_INPUT_BYTES` | `24000` | Максимальный размер JSON запроса |
| `AI_RETENTION_DAYS` | `30` | Хранение диалогов, от 1 до 90 дней |

При включённом провайдере отсутствие модели, ключа или положительных тарифов — ошибка конфигурации. Не вставляйте ключи в shell-команды, Git, JSON-запросы браузера или тексты чата.

Вызов выполняется `fetch` через **Responses API** по фиксированному адресу `https://api.openai.com/v1/responses`, с `store:false`, строгой JSON Schema в `text.format`, без внешних инструментов. Результат повторно проверяется Zod и сопоставляется с допустимыми ID. `store:false` отключает сохраняемое состояние ответа; это не эквивалент Zero Data Retention и не меняет прочие применимые правила хранения провайдера.

Перед каждым вызовом отдельная транзакция с advisory lock атомарно резервирует верхнюю оценку стоимости. Резерв основан на UTF-8 байтах запроса с дополнительным запасом для служебных токенов, лимите выходных токенов и указанных максимальных тарифах. После ответа расход заменяется значениями из `usage`. Неопределённый сетевой сбой/таймаут удерживает полную оценку, поскольку запрос уже мог быть оплачен. Не завершившиеся после аварии резервы автоматически не освобождаются. Изменение цен провайдером требует обновления конфигурации. Этот журнал не видит расходы того же ключа в других приложениях: настройте бюджет проекта и уведомления также на стороне провайдера.

Повторяется только явно отклонённый HTTP 429 — один раз после 150 мс, в рамках общего таймаута. Сетевые ошибки и HTTP 5xx не повторяются автоматически. Невалидный ответ, отказ модели, недостаток бюджета, превышение лимита, таймаут или отключённый провайдер переключают результат на детерминированную обработку.

`rerankRecommendations({pool,userId,candidates,context,config?,fetchFn?})` экспортируется для карьерного модуля. Вход: максимум 8 `{eventId,facts:[{id,text}]}`. Выход: `{source,eventIds,reasonFactIds,usageId?,fallbackReason?}`. Выбираются 1–3 существующих события и только их существующие факторы. Вызов должен выполняться вне транзакции записи бизнес-операции: журнал оплачиваемого запроса фиксируется независимо и не должен откатываться вместе с планом развития. Доступ и актуальность кандидатов повторно проверяет вызывающий карьерный модуль.

## Проверки и ограничения

`tests/guide.test.ts`, `tests/ai.test.ts`: локализованная выдача, роли, версии, срок действия, публикация, контакты, отзывы, чужие диалоги, идемпотентность, удаление/retention, конкурентный бюджет, strict Responses API, ошибочные ID, отказ, HTTP 429, timeout и финансовый журнал. Провайдер в тестах подменён функцией `fetchFn`; реальные ключи и деньги не используются.

`tests/backend-http.test.ts` запускает настоящий `createApp` на случайном локальном порту с отдельной схемой PostgreSQL. Проверяются cookie, Origin, CSRF, все подключённые доменные модули, HR-маршруты `/admin/mentors`, IDOR, приватные планы/диалоги, отзыв источника после сохранённого ответа, replay и изменение роли/связанного профиля. Внешние провайдеры выключены.

Для интеграционных тестов задайте отдельный `TEST_DATABASE_URL`; каждый набор создаёт случайную PostgreSQL-схему, прогоняет миграции и удаляет только эту схему.

Реальные регламенты, утверждённые переводы и контакты должен предоставить владелец данных организации. В seed 15 явно синтетических статей; реальных контактов нет. Интеграция заявок IT/HR реализуется отдельным модулем после настройки коннектора; путеводитель не выдаёт вымышленные номера внешних заявок. Семантические эмбеддинги и NVIDIA не включены.

Официальные источники реализации:

- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) — `text.format`, строгая схема, отказы.
- [Переход на Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses) — структура Responses и `store:false`.
- [OpenAI Data Controls](https://developers.openai.com/api/docs/guides/your-data) — ограничения и правила хранения.
- [OpenAI API Pricing](https://developers.openai.com/api/docs/pricing) — проверить тарифы выбранных моделей перед включением.
