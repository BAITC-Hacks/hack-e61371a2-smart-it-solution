# Проверка NVIDIA Brev — 23 сентября 2026

## Итог

Qwen3-4B-Instruct-2507 работает на существующей NVIDIA A10G в Brev через vLLM 0.30.0. Backend подключён по приватному SSH-туннелю из Docker. В браузере на `/assistant` проверен ответ с отметкой «Подбор источников с ИИ» и ссылкой на утверждённую демонстрационную статью.

Развёртывание зафиксировано в `NVIDIA_BREV_SETUP.md`; команды и версии находятся в `infra/brev/`. OpenAI в живых проверках не использовался. GPU-машина оставлена запущенной для работы помощника.

## Живой API smoke

Команда: `docker compose --env-file .env.brev -f compose.yaml -f compose.brev.yaml exec -T back node --input-type=module < infra/brev/smoke.mjs`.

| Проверка | Результат | Задержка после прогрева |
| --- | --- | --- |
| RU: содержание демо-инструкции про ноутбук | `source=ai`, 1 цитата | 1881 мс |
| KK: содержание демо-инструкции про ноутбук | `source=ai`, 1 цитата | 1847 мс |
| RU: собственная текущая роль и грейд | `source=ai`, 1 проверенный факт | 726 мс |
| Повтор каждого `Idempotency-Key` | Тот же ответ/ID | Пройдено |
| `/v1/models` без токена | HTTP 401 | Пройдено |
| `/v1/models` с серверным токеном | HTTP 200, ожидаемая модель | Пройдено |

RU и KK запросы выполнялись одновременно. Замеры относятся к трём синтетическим вопросам; отдельная нагрузочная проверка и оценка качества на корпусе организации ещё нужны. Временные диалоги API smoke удалены; журнал запросов сохранён.

Первый живой прогон выявил неправильный выбор ID и чрезмерный отказ от релевантных демо-материалов. Исправлено: разрешённые ID перечислены в JSON Schema, инструкция описывает выбор существующих ссылок; серверные проверки ID и прав сохранены. После исправления все три сценария прошли.

## Приложение и восстановление

- Backend, PostgreSQL, Front и SSH tunnel имеют healthy status; worker работает.
- После `docker compose ... restart back` Compose перезапустил зависимый tunnel. После установления SSH `/health` модели и `/api/v1/health/ready` вернули 200.
- После этого в браузере отправлен вопрос про демо-инструкцию; отображены ответ `ai`, отметка демонстрационного материала и рабочая ссылка на статью.
- Во время переподключения возможен штатный fallback; готовность туннеля отражена отдельным healthcheck.
- Снимок потребления: GPU 18 259 / 23 028 MiB, RAM контейнера около 4.1 GiB при 15.42 GiB на VM.
- Приложение работает на Mac в Docker, модель — в Brev. Публичное размещение приложения на отдельном сервере не выполнялось.

## Границы данных и передача Front

Помощник выбирает факты и ссылки, текст собирает сервер. В базе пока демонстрационные инструкции; реальные контакты/регламенты публикует ответственное лицо организации. Отсутствующие сведения не выдумываются.

Для следующего frontend PR по обновлённому контракту:

1. В AI-настройках показывать `provider`, `costBasis` и `gpuCostExcluded`: денежные поля означают OpenAI API, стоимость Brev учитывается по времени в его консоли.
2. Согласовать задержку кнопки нового запроса после аварии с текущим серверным lease 120 секунд; ранняя попытка не дублирует ответ, backend возвращает `MESSAGE_PROCESSING`.

`Front/**` сохранён в зоне ответственности тиммейта. Его актуальный экран чата уже работает с подключённой моделью.
