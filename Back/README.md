# Career Quest — Back

Сервер API, PostgreSQL, расчёты и интеграции с ИИ. Сейчас здесь зафиксированы границы разработки и конфигурация; сервер и команды запуска появятся в отдельном PR.

## Стек

Node.js 24.19, TypeScript 5.9, `node:http`, PostgreSQL через `pg`. Все запросы — параметризованный SQL, миграции — `.sql`; ORM не используется. Docker 29.1.3 для контейнеризации.

Указанные версии — требования проекта. При подготовке сборок необходимо проверить доступность точных релизов, Node-образа и совместимость; любые замены документировать в PR.

## Ответственность

- Контракт `/api/v1`, проверка входов, авторизация, RBAC и аудит.
- SQL-схема, миграции, импорт и проверка синтетических данных.
- Эффективные навыки, карьерные разрывы, фильтрация и рейтинг активностей.
- Запись, завершение, идемпотентность и транзакционный пересчёт прогресса.
- Агрегации HR, поиск, экспорт и административные операции.
- Путеводитель: утверждённые версии статей, контакты, правила маршрутизации и права.
- ИИ: разрешённый контекст, источники ответа, адаптеры OpenAI/NIM, лимиты и резервный режим.
- Health/readiness, структурированные логи, метрики, резервное копирование.

## Планируемая структура

```text
Back/
  src/
    http/            Маршруты, middleware, валидация, ошибки
    modules/         Доменная логика по функциональным модулям
    repositories/    SQL-запросы через pg
    ai/              OpenAI/NIM адаптеры, контекст, проверка ответов
    config/          Чтение и проверка переменных окружения
  db/
    migrations/      Версионированные SQL-миграции
    seeds/           Импорт исходного датасета
  knowledge/         Синтетические статьи и контакты для демо
  contracts/         OpenAPI и примеры DTO без секретов
  tests/             Доменная логика, API, SQL, AI-контракты
  .env.example       Шаблон конфигурации
  .env               Локальные секреты, исключены из Git
```

Это целевая структура; каталоги исходников создаются вместе с кодом. `Back` будет иметь собственные `package.json`, lock-файл, сборку и Dockerfile. Контракт API принадлежит backend; изменения, затрагивающие интерфейс, согласуются в PR.

## Конфигурация

Шаблон: [.env.example](.env.example). При первоначальной настройке скопировать его в `.env`, только если локального файла ещё нет. Существующий `.env` не перезаписывать.

- `AI_PROVIDER=disabled` позволяет разрабатывать без платных вызовов.
- Для OpenAI: установить новый `OPENAI_API_KEY`, доступные в проекте модели `AI_MODEL_FAST` / `AI_MODEL_RECOMMEND`, затем переключить провайдера на `openai`.
- Для Brev: использовать [инструкцию NVIDIA](NVIDIA_BREV_SETUP.md), заполнить `NIM_BASE_URL`, `NIM_MODEL`; провайдер — `nim`.
- `NIM_API_KEY` используется для аутентификации на inference endpoint, если она настроена. Это не NGC-ключ скачивания контейнера.
- Пока сервер не реализован, настройки не запускают запросы и не ограничивают расходы сами по себе. Проверка конфигурации, учёт расходов и fallback входят в план разработки.

Для локального запуска из `Back` будущий сервер должен явно загружать `.env` (например, через Node `--env-file=.env`); Compose получает этот файл через `env_file`. Секреты не включаются в Docker-образ и логи.
