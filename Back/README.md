# Career Quest — Back

Этапы 1–2: Node.js 24.19.0, TypeScript 5.9, `node:http`, PostgreSQL 17 через `pg`, SQL без ORM. Полный контракт — [contracts/API.md](contracts/API.md), параллельная работа — [TEAM_WORK.md](../TEAM_WORK.md).

## Реализовано

- Версионированные SQL-миграции с checksum и блокировкой конкурентного запуска.
- Каталог навыков/ролей, сотрудники, карьерные цели, мероприятия и история участия.
- JSON/CSV-импорт, проверка схемы и ссылок, preview, атомарный commit, SHA-256 дедупликация, аудит.
- Дополнительные профили и история без фиксированного списка ID. Исходный набор содержит 200 сотрудников, 60 навыков, 40 мероприятий и 2 743 участия.
- HttpOnly cookie-сессии на 8 часов, logout/revocation, hash токенов в БД, пароли scrypt, Origin/CSRF, ограничение попыток входа.
- Employee: собственный профиль; manager: себя и прямых подчинённых; HR: организация; admin: организация и импорт. Запрещённый профиль возвращает 404 без раскрытия его существования.
- Health/readiness и интеграционные проверки на реальной PostgreSQL.

Рекомендации, прогресс, HR-аналитика, путеводитель и AI-адаптеры относятся к следующим этапам.

## Запуск

Самый простой способ — `docker compose up -d --build --wait` из корня, затем http://localhost:8080.

Для backend-разработки используйте Node из `.nvmrc`:

```bash
# В корне
nvm install
nvm use
docker compose up -d db
cd Back
npm ci
# Только при отсутствии локального файла:
# cp .env.example .env
npm run migrate
npm run seed
npm run dev
```

Если `.env` уже существует, обновите только нужные настройки, не перезаписывая секреты. Локальная PostgreSQL опубликована на `localhost:5433`; шаблон содержит пароль исключительно локальной demo-среды. `DATASET_PATH=./data`, пути относятся к каталогу Back. Для клиента Vite `APP_ORIGIN=http://localhost:5173`.

Если порт 3001 занят контейнером, остановите его перед `npm run dev`: `docker compose stop back front` из корня. Либо работайте с контейнерным backend, как описано в TEAM_WORK.md.

## Аккаунты

При `DEMO_MODE=true` seed создаёт `demo.employee`, `demo.manager`, `demo.hr`, `demo.admin`. API выдаёт их через `/auth/demo-accounts`. При `DEMO_MODE=false` демо-вход и ранее созданные демо-сессии запрещены. Не включайте демо-вход для реальных данных.

Обычный аккаунт создаётся через `npm run account` с переменными окружения:

- `ACCOUNT_LOGIN`, `ACCOUNT_NAME`;
- `ACCOUNT_ROLE`: employee / manager / hr / admin;
- `ACCOUNT_EMPLOYEE_ID`: обязателен для employee и manager, существующий ID;
- `ACCOUNT_PASSWORD`: минимум 12 символов, передаётся через скрытый ввод/менеджер секретов, не через Git.

Команда создаёт новый аккаунт; существующий не перезаписывает. Пароль сохраняется только как salted scrypt hash. Профессия сотрудника не определяет права.

## Проверки

```bash
npm run build
TEST_DATABASE_URL=postgresql://career_quest:career_quest_local_only@localhost:5433/career_quest npm test
```

Интеграционный тест создаёт отдельную случайную схему `cq_test_*` и удаляет только её. Исходные таблицы приложения не очищаются. Нужна БД, где тестовому пользователю разрешено создавать схемы. Без TEST_DATABASE_URL интеграционный набор явно пропускается; CI всегда задаёт её.

Покрытие: исходный импорт, дополнительные профили, preview, неверные связи, дубли/конкурентный повтор, конфликт ID истории, права четырёх ролей, CSRF/Origin, выход, истечение сессии, отключённый аккаунт, парольный вход и выключенный DEMO_MODE.

## Структура и конфигурация

- `src/` — сервер, конфигурация, SQL-доступ, авторизация и импорт.
- `db/migrations/` — миграции; применённые файлы не изменять, добавлять следующие.
- `data/` — копия разрешённого синтетического набора хакатона.
- `contracts/` — договорённости с frontend.
- `tests/` — автоматические проверки.

`.env` исключён из Git и Docker build. Compose передаёт только необходимые параметры, OpenAI-ключ в контейнер не попадает.
