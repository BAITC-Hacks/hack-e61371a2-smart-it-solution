# Career Quest — Front

Полный frontend Career Quest: сотрудник, руководитель, HR и администратор.
React 19.2, TypeScript 5.9, Vite 7, Tailwind CSS 4, Radix UI, wouter.
Фронтенд подключён к локальному backend; изменения для совместимости обеих частей описаны в INTEGRATION.md.

## Возможности

- **Вход и доступ:** демо-роли, логин/пароль, восстановление сессии, OIDC при настройке организации, список и отзыв собственных сессий. Права проверяются сервером.
- **Карьера:** профиль, цель и история её изменений, оценённые и расчётные навыки, критические разрывы, прогресс, объяснимые рекомендации и обратная связь.
- **Обучение:** каталог и фильтры, условия участия, расписание и вместимость, запись/очередь/начало/завершение/отказ/перенос. История и корректировки с подтверждением.
- **Развитие:** планы на 30/90/180 дней, предпочтения, сравнение целей и модель «что, если», наставники и заявки, личные задания и достижения, благодарности, командные активности, награды по утверждённой политике.
- **Путеводитель:** поиск, категории, контекстные подсказки, статьи с источниками и контактами, обратная связь, обращения в настроенную систему. Отдельный поиск по смыслу с SQL fallback.
- **Помощник:** личные диалоги, история и удаление, ссылки на разрешённые данные, явное обозначение резервного ответа при отключённом ИИ.
- **HR:** разрывы навыков, сотрудники без следующего шага, участие и сравнение программ, фильтры, воронка, история оценок, сигналы участия, моделирование команды, подтверждаемые финансовые данные и ROI. Руководитель видит свою команду.
- **Управление:** редактор мероприятий с preview, сессии и переводы; версии и публикация базы знаний, темы, контакты и маршруты; аккаунты, аудит, расходы ИИ, управление семантическим индексом и проверкой качества.
- **Интеграции:** preview/commit JSON и CSV, новые/изменённые/неизменённые записи, предупреждения и история; LMS/HRIS с сопоставлением ID, подписки и история доставок, уведомления и календарь `.ics`.
- **Интерфейс:** RU/KZ/EN, мобильное меню, клавиатура, загрузки/ошибки/пустые состояния, разделение кода по страницам. PWA с публичным офлайн-экраном.

Корпоративные источники, статьи, переводы, контакты и награды отображаются из API. Интерфейс не создаёт вымышленные подтверждения внешних подключений. Условия и оставшиеся ограничения API описаны в [INTEGRATION.md](INTEGRATION.md).

## Запуск

Нужны Node.js **24.19.0** из `.nvmrc` и актуальный backend с полным набором миграций. Из корня репозитория:

```bash
APP_ORIGIN=http://localhost:5173 docker compose up -d --build --wait db back
cd Front
npm ci
npm run dev
```

Для PowerShell переменная задаётся перед запуском:

```powershell
$env:APP_ORIGIN = 'http://localhost:5173'
```

Открыть **http://localhost:5173**. По умолчанию Vite использует порт 5173 и направляет `/api` на `127.0.0.1:3001`. Для отдельной тестовой среды серверный proxy можно изменить переменной `CQ_API_PROXY_TARGET` в командной оболочке, сохранив относительный `/api/v1` в браузере. Адрес приложения должен совпадать с `APP_ORIGIN` backend. Альтернативный запуск сервера описан в [Back/README.md](../Back/README.md).

Все запросы клиента идут на **`/api/v1`** с того же origin. Front не требует `.env` с ключами. Сессия определяется HttpOnly cookie; изменяющие запросы передают CSRF, поддерживаемые операции — ключ идемпотентности. Пароли БД и ключи провайдеров остаются на сервере.

## Основные адреса

| Адрес | Раздел |
| --- | --- |
| `/login`, `/`, `/profile`, `/access` | Вход, обзор, профиль, права и сессии |
| `/people`, `/people/:id` | Доступные сотрудники и профиль |
| `/development`, `/people/:id/development` | Карьера и навыки |
| `/events`, `/events/:eventId`, `/history` | Обучение и история |
| `/growth?section=plans` | Планы развития |
| `/growth?section=forecast` | Сравнение и модель развития |
| `/growth?section=mentors`, `tasks`, `thanks`, `team`, `rewards` | Остальные вкладки развития |
| `/guide`, `/guide/articles/:articleId`, `/assistant` | Инструкции и помощник |
| `/notifications` | Личные уведомления и календарь |
| `/hr` | Аналитика организации или команды |
| `/events/manage`, `/events/new`, `/events/:eventId/edit` | Управление мероприятиями |
| `/guide/manage`, `/admin/growth` | База знаний и программы развития |
| `/admin/imports`, `/admin/settings` | Импорт, аккаунты и интеграции |

Неизвестные адреса и недоступные данные имеют отдельные состояния. Прямой переход по адресу не обходит серверные права.

## Сборка и размещение

```bash
npm run typecheck
npm run build
```

Сборка создаёт `dist/`. Веб-сервер должен отдавать `index.html` для клиентских маршрутов и передавать `/api/v1` backend с того же origin. Для полного контейнерного запуска:

```bash
APP_ORIGIN=http://localhost:8080 docker compose up -d --build --wait
```

Открыть **http://localhost:8080**. Интеграционные настройки запуска и результаты проверок описаны в [общем отчёте](../INTEGRATION_VERIFICATION.md).

PWA регистрируется только в production-сборке. Установка доступна по HTTPS или на localhost, когда браузер предлагает её. Service worker сохраняет только значки, манифест, публичный `offline.html` и его скрипт переводов `offline.js`. Ответы API, страницы профилей, авторизованный HTML и данные сотрудников в офлайн-кеш не записываются. Для просмотра личного пространства нужна сеть. Значки PNG воспроизводятся из SVG командой `node scripts/render-icons.mjs` с установленным браузером Playwright.

## Проверки

```bash
npx playwright install chromium
npm run test:e2e
```

По умолчанию запускаются 21 контрактная UI-проверка; реальные интеграционные сценарии включаются отдельно и требуют **одноразовую тестовую БД**. Команды, условия и сценарии — в [tests/README.md](tests/README.md).

Результат интеграционной приёмки **23.09.2026: 39 браузерных сценариев прошли**:

- 21 UI-проверка с явными моками контракта, включая длительные ответы ИИ, повтор сообщений и независимую настройку embeddings;
- 16 сценариев с объединённым backend на основе **`2f985c4`** с обновлением **`5f14d1a`** и PostgreSQL: вход/роли/импорт, карьерный цикл, развитие и LMS, база знаний/помощник/администрирование, HR/уведомления/календарь/отзыв сессии;
- 2 проверки production PWA: состав офлайн-кеша и перевод офлайн-экрана при строгой политике CSP.

Браузер — Edge 153; локальная приёмочная PostgreSQL — 18.4, целевой Compose использует PostgreSQL 17. Внешние ИИ-провайдеры, OIDC, корпоративные мессенджеры и системы заявок в этих проверках не вызывались. Их подключение требует серверной конфигурации организации. TypeScript и production-сборка прошли.

## Структура

- `src/App.tsx` — сессия, маршруты и лениво загружаемые страницы.
- `src/api.ts`, `src/api-errors.ts` — клиент API и переводы ошибок.
- `src/pages/` — вход, обзор, сотрудники, профиль, права и импорт.
- `src/features/career/` — карьера, обучение и история.
- `src/features/growth/` — планы, моделирование, социальные функции и награды.
- `src/features/guide/` — путеводитель, редактор, помощник и обращения.
- `src/features/administration/` — аккаунты, аудит, интеграции и семантический поиск.
- `src/features/platform/` — HR, уведомления, сессии и общие формы.
- `public/` — PWA и общедоступный офлайн-экран.
- `tests/` — проверки контракта, реального API и production PWA.
