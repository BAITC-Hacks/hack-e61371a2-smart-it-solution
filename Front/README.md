# Career Quest — Front

Рабочий интерфейс этапов 1–2 для сотрудника, руководителя, HR и администратора.
React 19.2, TypeScript 5.9, Vite 7, Tailwind CSS 4, Radix UI и wouter.
Границы разработки определены в [TEAM_WORK.md](../TEAM_WORK.md), запросы — в
[контракте API](../Back/contracts/API.md).

## Возможности

- Адаптивная оболочка: боковое меню, мобильная навигация, клавиатурное управление,
  понятные состояния загрузки, ошибки и отсутствия данных.
- Демо-вход для четырёх ролей и обычный вход по логину/паролю. Восстановление
  сессии после обновления страницы, выход и обработка истёкшей сессии.
- Обзор с настоящими счётчиками сотрудников, навыков, активностей и участия из
  `GET /workspace`; версия и дата текущего набора.
- Поиск доступных сотрудников по имени, должности и отделу, пагинация,
  просмотр профиля, текущего грейда и записанной карьерной цели.
- Страница прав доступа. Сотрудник видит свой профиль, руководитель — свой
  профиль и прямых подчинённых, HR и администратор — профили организации.
  Разрешения и доступ к каждому профилю проверяет сервер.
- Администратор выбирает JSON/CSV, получает предпросмотр и подробности ошибок,
  отдельно подтверждает применение и видит историю импортов. Замена или
  удаление файла сбрасывает предпросмотр; ответ устаревшего запроса его не
  восстанавливает. Повторно загруженный пакет не применяется ещё раз.
- Русский, казахский и английский интерфейс (`ru`, `kk`, `en`; в переключателе
  RU/KZ/EN). Ручной выбор языка сохраняется; до такого выбора учитывается язык
  связанного профиля.

Расчёт карьерного прогресса, рекомендации, запись на обучение, HR-аналитика,
путеводитель и ИИ-чат относятся к следующим этапам. В текущем интерфейсе они
не представлены как работающие функции. Счётчики каталогов не означают
наличие страниц управления этими каталогами.

## Локальная разработка

Нужны Node.js **24.19.0** из корневого `.nvmrc`, npm и запущенный backend.
Для контейнерного backend нужны Docker и Compose. Из корня репозитория,
как описано в [TEAM_WORK.md](../TEAM_WORK.md):

```bash
APP_ORIGIN=http://localhost:5173 docker compose up -d --build --wait db back
```

Эквивалент в PowerShell:

```powershell
$env:APP_ORIGIN = 'http://localhost:5173'
docker compose up -d --build --wait db back
```

Compose запускает PostgreSQL и API, применяет миграции и загружает синтетический
набор. Локальный файл с ключами не требуется. Затем:

```bash
cd Front
npm ci
npm run dev
```

Открыть **http://localhost:5173**. Используйте именно этот адрес: backend
проверяет Origin изменяющих запросов. API доступен на порту 3001; Vite
направляет `/api` на `http://127.0.0.1:3001`. Порт 5173 фиксирован.
Другой способ запуска backend описан в [Back/README.md](../Back/README.md).

## API и конфигурация

Все запросы клиента идут на относительный **`/api/v1`** с того же origin.
Переопределения `VITE_API_BASE_URL` нет; переменные окружения для Front не
требуются. `.env.example` содержит только пояснение этой настройки.

Сессия хранится сервером и определяется HttpOnly cookie; CSRF-токен приходит
с ответом входа или восстановления сессии и передаётся в изменяющих запросах.
После 401 интерфейс убирает данные прежнего пользователя. В Front не должны
попадать пароли БД, ключи OpenAI/NVIDIA и другие серверные секреты.

## Маршруты

| Адрес | Содержимое |
| --- | --- |
| `/login` | Демо-вход или вход по логину и паролю |
| `/` | Обзор рабочего пространства |
| `/people` | Список профилей в пределах доступа пользователя |
| `/people/:id` | Профиль сотрудника, доступность проверяет API |
| `/profile` | Собственный профиль, если он связан с аккаунтом |
| `/access` | Возможности текущей роли |
| `/admin/imports` | Предпросмотр, применение и история импортов; только admin |

Защищённые страницы требуют сессию. Неизвестные адреса и недоступные профили
показывают отдельное состояние с переходом обратно в приложение.

## Сборка и размещение

```bash
npm run typecheck
npm run build
```

`npm run build` проверяет TypeScript и создаёт статические файлы в `dist/`.
При размещении сервер должен возвращать `index.html` для клиентских маршрутов
и передавать `/api/v1` существующему backend на том же origin. Его `APP_ORIGIN`
должен совпадать с адресом приложения. Такая схема уже предусмотрена общим
контейнерным запуском; frontend не меняет корневые Compose и инфраструктуру.

Для полной локальной демонстрации из корня используется
`docker compose up -d --build --wait` и адрес **http://localhost:8080**.
Если ранее был задан `APP_ORIGIN` для Vite, установите его равным
`http://localhost:8080` перед этим запуском.

## Проверки

```bash
npx playwright install chromium
npm run test:e2e
```

Обычный запуск выполняет **12 браузерных проверок с явными моками контракта**:
вход/выход, ошибки, восстановление и истечение сессии, права, сотрудники,
поиск, пагинация, мобильное меню, языки и безопасный порядок импорта.

Отдельные **6 проверок с настоящими API и PostgreSQL** включаются через
`CQ_E2E_REAL_API=1` и требуют одноразовую мигрированную тестовую базу с
демоданными. Они проверяют парольный вход, четыре роли, недоступные чужие
профили, сессии, применение импорта, дубли и серверную валидацию. Для сценария
обычного аккаунта передаются тестовые учётные данные через переменные
окружения. Моки не подтверждают серверную авторизацию или транзакции.

**Проверенный результат 23.09.2026: 18/18 сценариев прошли** в Edge 153,
включая все 6 проверок с неизменённым backend из коммита `4bccbb3` и реальной
PostgreSQL 18.4. Этот результат относится к указанной версии backend;
новые миграции из `main` (`8961170`) в этот прогон не входили.
Целевой контейнерный backend использует PostgreSQL 17. Подробные команды,
настройки браузера и требования к базе — в [tests/README.md](tests/README.md).

`node_modules/`, `dist/`, `playwright-report/` и `test-results/` исключены из Git.

## Структура

- `src/App.tsx` — сессия, оболочка, навигация и маршруты.
- `src/api.ts` — типы контракта и HTTP-клиент.
- `src/i18n.tsx`, `src/app.copy.ts`, `src/pages/*.copy.ts` — локализация.
- `src/pages/` — вход, обзор, сотрудники, профиль, права и импорт.
- `src/components/ui.tsx`, `src/styles.css`, `src/pages/*.css` — общие
  компоненты, дизайн-токены и адаптивные стили.
- `tests/`, `playwright.config.ts` — браузерные проверки и их конфигурация.
